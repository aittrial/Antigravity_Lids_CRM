# CLAUDE.md — Документация проекта Lids CRM System

## Что это за проект?

CRM-система для управления лидами образовательного центра **Tel-Ran** (курсы QA-тестирования, программирования, бухгалтерии). Основная задача — принимать, хранить, фильтровать и отслеживать потенциальных студентов (лидов) с цветовыми статусами обработки.

Приложение развёрнуто на **Railway** (ранее Heroku) и доступно через веб-браузер. Бэкапы и уведомления о новых лидах идут в **Telegram-канал** команды.

## База данных — схема таблиц

### Таблица `leads` — основная

```sql
CREATE TABLE leads (
    id            SERIAL PRIMARY KEY,
    full_name     TEXT,                          -- ФИО лида
    phone         TEXT,                          -- Телефон
    whatsapp      TEXT,                          -- WhatsApp (если отличается от телефона)
    email         TEXT,                          -- Email
    course_name   TEXT,                          -- Интересующий курс
    preferred_time TEXT,                         -- Удобное время для звонка (строка, напр. "14:00")
    source        TEXT,                          -- Источник лида
    comment       TEXT,                          -- Комментарий менеджера
    status_color  VARCHAR(50) DEFAULT 'white',   -- Цветовой статус обработки
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    archived_at   TIMESTAMP DEFAULT NULL         -- NULL = активный, иначе = в архиве
);
```

**Архивирование** реализовано через `archived_at`: мягкое удаление (soft delete). Лид считается активным, пока `archived_at IS NULL`.

### Таблица `allowed_emails` — доступы сотрудников

```sql
CREATE TABLE allowed_emails (
    email VARCHAR(255) PRIMARY KEY,
    role  TEXT DEFAULT 'admin'   -- 'admin', 'analyst', 'superadmin'
);
```

### Таблица `settings` — системные настройки

```sql
CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT
);
```

Используется для хранения `archive_date` — даты последней массовой архивации.

## Система ролей и доступов

### Роли

| Роль | Как войти | Описание |
|---|---|---|
| `superadmin` | По мастер-паролю (`MASTER_PASSWORD`) | Полный доступ ко всем функциям |
| `admin` | По Email из таблицы `allowed_emails` | Управление лидами, без удаления и управления пользователями |
| `analyst` | По Email из таблицы `allowed_emails` | Только просмотр аналитики |

### Матрица доступа

| Страница / Действие | analyst | admin | superadmin |
|---|:---:|:---:|:---:|
| 📊 Аналитика | ✅ | ✅ | ✅ |
| 👥 Список лидов | ❌ | ✅ | ✅ |
| ➕ Новый лид | ❌ | ✅ | ✅ |
| 📂 База данных (экспорт) | ❌ | ✅ | ✅ |
| Telegram-бэкап | ❌ | ✅ | ✅ |
| 📦 Все в архив | ❌ | ✅ | ✅ |
| 🔥 Удалить все лиды | ❌ | ❌ | ✅ |
| 🔑 Управление доступами | ❌ | ❌ | ✅ |

### Аутентификация (auth.py)

- Состояние хранится в `st.session_state["authenticated"]` и `st.session_state["role"]`
- Суперадмин: проверяет введённый пароль против `os.getenv("MASTER_PASSWORD")`
- Сотрудник: ищет email в таблице `allowed_emails`, получает роль из БД
- `logout()` сбрасывает session state и вызывает `st.rerun()`

## Страницы приложения (main.py)

### 📊 Аналитика

- Загружает все лиды через `get_leads(mode="all")`
- Показывает два блока метрик: **Всего** и **За 7 дней**
- Метрики разбиты по 7 цветовым статусам
- Графики (Plotly):
  - Круговая диаграмма источников за 7 дней
  - Area-chart динамики лидов за 7 дней
  - Горизонтальный Bar-chart по статусам за 7 дней (без белого)
- Доступна роли `analyst`

### 👥 Список лидов

- Фильтры: поиск по ФИО/телефону, диапазон дат, статус, источник
- Два таба: **Активные** и **Архив**
- Активные: `get_leads(mode="active", limit=50)`
- Архив: `get_leads(mode="archive", limit=50, offset=...)` с пагинацией по 50 штук
- **Важно:** для архива `start_date` и `end_date` передаются как `None` — даты не фильтруют архив
- Каждый лид рендерится через `render_leads_list()`

### Карточка лида (render_leads_list)

Каждый лид выглядит так:
1. **Цветная шапка** (цвет фона = статус) с номером, датой, временем звонка, ФИО, телефоном
2. **Expander "🛠 Управление"** содержит:
   - Кнопка **WhatsApp** — ссылка `https://wa.me/{digits_only}`, открывается в новой вкладке
   - **Блок копирования** — `st.code()` с полными данными лида
   - Кнопка **"📦 В архив"** (только для активных, только `admin`/`superadmin`)
   - **Форма редактирования**: все поля + selectbox для статуса и источника
   - Кнопка **"💾 Сохранить изменения"** вызывает `update_lead()`

### ➕ Новый лид

- `st.form` с ключом `f_new_{form_key}` (форм-кей инкрементируется при сабмите — это очищает форму)
- Обязательные поля: **ФИО** и **Телефон**
- После создания: показывает success-сообщение 5 секунд (`time.sleep(5)`), потом `st.rerun()`
- Отправляет уведомление в Telegram через `send_telegram_notification()`

### 📂 База данных

3 колонки:
- **Экспорт**: скачать Excel + кнопка отправки бэкапа в Telegram (Excel + CSV одновременно)
- **Архивация**: кнопка "📦 ВСЕ В АРХИВ" — вызывает `set_archive_threshold()`
- **Очистка**: чекбокс подтверждения + кнопка "🔥 УДАЛИТЬ ВСЁ" (только `superadmin`)
- **Импорт**: загрузка `.xlsx`, парсит колонки `full_name` и `phone`, source="Excel Import"

### 🔑 Администрирование

- Только `superadmin`
- Добавление email + роль (`admin` / `analyst`)
- Список всех пользователей с кнопкой удаления

## Функции database.py

### `get_connection()`
Подключается к PostgreSQL через переменные окружения. `sslmode='require'` обязателен для Railway. Возвращает `conn` или `None`.

### `init_db()`
Создаёт таблицы при старте (`CREATE TABLE IF NOT EXISTS`). Содержит `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` для миграции старых баз (добавление `archived_at`, `whatsapp`, `role`). Вызывается в начале `main.py`.

### `get_leads(search_query, start_date, end_date, mode, status_filter, source_filter, limit, offset)`
Основная функция выборки с фильтрами:
- `mode="active"` → `AND archived_at IS NULL`
- `mode="archive"` → `AND archived_at IS NOT NULL`
- `mode="all"` → без фильтра по архиву, без `LIMIT`
- Поиск: `ILIKE '%query%'` по `full_name` и `phone`
- Статус: маппинг русских названий → английские ключи
- Даты: применяются только для `mode != "archive"`
- Возвращает `list[dict]`

### `add_lead(full_name, phone, email, course_name, preferred_time, source, comment, status_color, whatsapp)`
INSERT в таблицу `leads`.

### `update_lead(lead_id, **kwargs)`
UPDATE по id через `**kwargs`. Каждый ключ — отдельный UPDATE-запрос.  
**Известный баг:** функция определена дважды (строки 122 и 133) — это дублирование без последствий, но надо убрать.

### `delete_lead(lead_id)`
Hard delete по id. **Внимание:** в UI кнопки удаления нет — функция импортирована но не используется в интерфейсе.

### `set_archive_threshold()`
Массовая архивация: устанавливает `archived_at = NOW()` для всех активных лидов + сохраняет дату в `settings`.

### `archive_single_lead(lead_id)`
Архивирует один лид: `UPDATE leads SET archived_at = NOW() WHERE id = ?`.

### `clear_all_leads()`
`TRUNCATE TABLE leads RESTART IDENTITY CASCADE` — удаляет все лиды и сбрасывает счётчик id.

## Известные проблемы и техдолг

### Критичные

1. **Дублирующаяся функция** — `update_lead()` определена дважды в `database.py` (строки 122 и 133). Вторая переопределяет первую — работает корректно, но нужно удалить дубль.

### Некритичные

3. **`delete_lead()` не используется в UI** — функция импортирована в `main.py`, но кнопки удаления в интерфейсе нет.

4. **`time.sleep(5)` в форме нового лида** — блокирует поток Streamlit на 5 секунд. Можно заменить на `st.toast()` или убрать задержку.

5. **Google OAuth закомментирован** — в `.env.example` есть `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` (строки 7–8). Планировалась OAuth-авторизация через Google, но не реализована.

6. **Динамический SQL в update_lead** — `f"UPDATE leads SET {key} = %s"` использует f-string для имени колонки. Значение защищено параметром `%s`, но имя колонки не валидируется. При передаче вредоносного имени ключа возможна SQL-инъекция. Для продакшена стоит добавить whitelist допустимых ключей.

7. **Отсутствует валидация номера телефона** — принимается любая строка.

## Паттерны, которые используются в коде

### Управление соединением с БД
Каждая функция в `database.py` сама открывает и закрывает соединение:
```python
conn = get_connection()
if not conn: return []
try:
    cur = conn.cursor()
    # ... работа ...
    conn.commit()
finally:
    conn.close()
```

### Очистка формы через form_key
```python
# При создании лида инкрементируем ключ → форма пересоздаётся
st.session_state.form_key += 1
# Форма использует этот ключ
with st.form(key=f"f_new_{st.session_state.form_key}"):
```

### Пагинация архива через session_state
```python
st.session_state.archive_page_number  # текущая страница
offset_arch = current_page * limit_arch  # сдвиг = страница × 50
```

### Цветные карточки лидов через HTML
```python
st.markdown(f'<div style="background-color:{color}; ...">...</div>', unsafe_allow_html=True)
```

## Как добавить новую функцию (чеклист)

### Новое поле к лиду
1. `database.py` → `ALTER TABLE leads ADD COLUMN IF NOT EXISTS new_field TEXT;` в `init_db()`
2. `database.py` → добавить `new_field=''` в сигнатуру `add_lead()` и в INSERT
3. `main.py` → добавить поле в форму "Новый лид"
4. `main.py` → добавить поле в `render_leads_list()` (блок копирования + форма редактирования)
5. `main.py` → добавить поле в `send_telegram_notification()` если нужно

### Новый источник или курс
1. `main.py` → добавить строку в `SOURCE_OPTIONS` или `COURSE_OPTIONS`

### Новый статус (цвет)
1. `main.py` → добавить ключ в `COLOR_KEYS`
2. `main.py` → добавить русское название в `FILTER_COLOR_MAP`
3. `main.py` → добавить hex-цвет в `get_status_color()`
4. `main.py` → добавить в `c_map` в блоке аналитики (строка ~156)

### Новая роль пользователя
1. `auth.py` → добавить роль в логику `check_password()` (вкладка "Сотрудник")
2. `main.py` → добавить проверки `if user_role == "new_role"` в нужных местах
3. `database.py` → `add_allowed_email()` уже принимает произвольную роль через параметр

### Новая страница
1. `main.py` → добавить пункт в список `menu` внутри `main()` с учётом роли
2. `main.py` → добавить `elif choice == "..."` блок в конце `main()`

## Важные особенности Streamlit, используемые в проекте

- `st.rerun()` — перезапускает скрипт целиком (используется после изменений данных)
- `st.session_state` — хранит состояние между ревалидациями (роль, страница архива, ключ формы)
- `st.form()` — форма отправляется одним кликом, не триггерит rerun на каждый инпут
- `st.expander()` — сворачиваемый блок (используется для управления каждым лидом)
- `unsafe_allow_html=True` — используется для цветных карточек и WhatsApp-кнопки
- `st.tabs()` — вкладки "Активные" / "Архив" в списке лидов

### Правила при внесении изменений

1. **Не ломай существующие функции ради новых.** Перед добавлением новой возможности убедись, что все пункты чеклиста выше остаются рабочими.

2. **Проверяй все режимы get_leads.** Если меняешь `database.py → get_leads()`, проверь работу для `mode="active"`, `mode="archive"` и `mode="all"` — у них разная логика фильтрации дат и пагинации.

3. **Не трогай form_key без понимания.** `st.session_state.form_key` отвечает за очистку формы нового лида. Изменение логики сломает очистку.

4. **После изменений в init_db() — проверь обратную совместимость.** Миграции используют `ADD COLUMN IF NOT EXISTS` — новые колонки не должны ломать старые данные.

5. **Telegram-уведомления — не блокирующие.** Ошибка отправки в Telegram не должна прерывать основной флоу создания лида. Проверь, что `send_telegram_notification()` обёрнута в `try/except`.

6. **Проверяй обе вкладки авторизации.** Изменения в `auth.py` могут сломать вход как суперадмина, так и сотрудника — тестируй оба пути.
